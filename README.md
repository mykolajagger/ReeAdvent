# ReeAdvent

Комерційна версія адвент-календаря для пар. Лендинг із замовленням, оплата (Monobank acquiring), вхід за посиланням на пошту, приватний календар на 24 дні з обраної дати.

**Стек:** Cloudflare Pages (статика `public/`) + Pages Functions (`functions/api`, код у `src/`) + D1 (SQLite). Жодних залежностей у рантаймі.

## Структура
- `public/` — лендинг (`index.html`), застосунок календаря (`app/`), сторінка після оплати (`thanks.html`), юридичні **чернетки** (`legal/`)
- `src/api.js` — API: замовлення, оплата, вхід, календар · `src/logic.js` — підбір завдань · `src/content.js` — контент (300+ ідей) · `src/payments.js`, `src/email.js`
- `migrations/` — схема D1 · `dev/` — локальний сервер і автотести

## Локально
```bash
npm test                      # автотести (потрібен Node 22+)
npm run dev                   # http://localhost:8788 — SQLite у пам'яті, оплата й пошта — заглушки
# листи dev-режиму: http://localhost:8788/dev/outbox
# змінити «поточний час»: NOW_OVERRIDE=2026-12-12T08:00:00Z npm run dev
```

## Як це працює
1. Лендинг → `POST /api/orders` (імена, пошти, місто, область, **дата старту**, згоди 18+/оферта) → рахунок Monobank.
2. Monobank викликає webhook → сервер **перепитує статус інвойсу** власним токеном (тілу вебхука не вірить) → `markPaid` створює календар і двох учасників та шле обом лист із одноразовим посиланням (7 днів).
3. Посилання `/app/#login=TOKEN` (токен у фрагменті, щоб поштові сканери його не «спалили») → cookie-сесія. Далі вхід через запит нового посилання на пошту.
4. Кожен заповнює анкету; коли обоє готові — складається розклад (зберігається в D1, змінити не можна). Кожне вікно починається з **питання дня** (спільне для обох, рівень відповідає обраному «рівню пікантності»): поки людина не відповість партнеру, сервер не віддає завдань; відповідь не редагується, відповідь партнера з'являється, щойно він відповів. Вікна відкриваються о 07:00 за Києвом, починаючи з обраної дати; якщо дата минула до оплати — старт наступного дня.
5. Усю Україну покриває `{city}` у пошукових запитах; елементи з тегом `zk` показуються лише для Закарпатської області.

## Запуск у продакшн (чекліст)
1. Створити D1 `reeadvent-db` і виконати SQL з `docs/d1-console.sql` у консолі D1 (або `npx wrangler d1 create …` + міграції; приклад конфігу в `docs/wrangler.example.toml`). Файл `wrangler.toml` у корені не тримаємо: тоді Pages бере біндінги й змінні з дашборда.
2. Cloudflare Pages → підключити цей репозиторій, build output `public`, прив'язати D1 (binding `DB`) у налаштуваннях Pages. Змінні: `PRICE_UAH`, `BASE_URL`, `PAYMENT_MODE=monobank`, `EMAIL_MODE=resend`, `EMAIL_FROM`. Секрети: `MONOBANK_TOKEN`, `RESEND_API_KEY`.
3. Resend: підтвердити домен відправника (SPF/DKIM), інакше листи потраплятимуть у спам.
4. Monobank acquiring: отримати токен мерчанта; webhook встановлюється самим запитом створення інвойсу (`webHookUrl`).
5. **Юридичне:** замінити чернетки `public/legal/*` текстами від юриста/бухгалтера; за потреби політика зберігання й видалення даних.
6. Окремий домен, Cloudflare Turnstile на форму замовлення (антибот) — рекомендовано.
